## 1. 프로젝트 개요

### 1.1 목적
**AICraft_Figma**는 Figma 디자인 파일을 **WebSquare 컴포넌트(XML)**로 변환하는 도구입니다.

### 1.2 주요 기능
1. Figma URL로 디자인 파일 불러오기
2. 노드 트리 탐색 및 시각화
3. Figma 노드 → WebSquare 컴포넌트 매핑
4. 시그니처 기반 자동 매핑 (클러스터)
5. 키워드 기반 기본 매핑 규칙
6. XML 코드 생성 및 내보내기
7. 매핑 규칙 Export/Import (프로젝트 간 공유)

### 1.3 기술 스택
| 영역 | 기술 |
|-----|------|
| **프론트엔드** | React 18, TypeScript, Vite 5, Tailwind CSS |
| **백엔드** | Node.js, HTTP Server (Express 없음), tsx |
| **데이터베이스** | SQLite (better-sqlite3) |
| **테스트** | Vitest, React Testing Library, MSW |
| **외부 API** | Figma REST API |

## 3. 데이터베이스 스키마

### 3.1 테이블 구조

#### projects
```sql
CREATE TABLE projects (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
```

#### settings (프로젝트별 설정)
```sql
CREATE TABLE settings (
  project_id TEXT NOT NULL,
  key        TEXT NOT NULL,
  value      TEXT NOT NULL,
  PRIMARY KEY (project_id, key)
);
```
**주요 키:**
- `figma-token`: Figma API 액세스 토큰
- `css-list`: CSS 파일 목록 (JSON)
- `css-class-mapping`: 컴포넌트별 CSS 클래스 매핑 (JSON)
- `export-path`: XML 내보내기 경로
- `cluster-include-node-name`: 클러스터 시그니처에 노드 이름 포함 여부

#### registry (컴포넌트 레지스트리)
```sql
CREATE TABLE registry (
  id         TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  name       TEXT NOT NULL,      -- 예: "Button", "Input"
  tagName    TEXT NOT NULL,      -- 예: "w2:button", "w2:input"
  properties TEXT DEFAULT '{}',  -- JSON: 기본 속성들
  UNIQUE(project_id, name)
);
```

#### node_mappings (노드-컴포넌트 매핑)
```sql
CREATE TABLE node_mappings (
  id                  TEXT PRIMARY KEY,
  project_id          TEXT NOT NULL,
  figma_file_key      TEXT NOT NULL,
  figma_root_node_id  TEXT,
  figma_node_id       TEXT NOT NULL,
  figma_node_name     TEXT NOT NULL,
  figma_node_type     TEXT,
  registry_id         TEXT,
  registry_name       TEXT,
  registry_tag        TEXT,
  custom_attrs        TEXT DEFAULT '{}',
  status              TEXT DEFAULT 'pending',
  created_at          TEXT NOT NULL,
  updated_at          TEXT NOT NULL,
  UNIQUE(project_id, figma_file_key, figma_root_node_id, figma_node_id)
);
```

#### mapping_clusters (자동 매핑 클러스터)
```sql
CREATE TABLE mapping_clusters (
  id              TEXT PRIMARY KEY,
  project_id      TEXT NOT NULL,
  signature       TEXT NOT NULL,
  signature_data  TEXT NOT NULL,
  registry_id     TEXT NOT NULL,
  registry_name   TEXT NOT NULL,
  custom_attrs    TEXT DEFAULT '{}',
  sample_count    INTEGER DEFAULT 1,
  source          TEXT DEFAULT 'generated',
  variant_mode    TEXT,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL,
  UNIQUE(project_id, signature)
);
```

## 4. 핵심 로직 상세

### 4.1 시그니처 기반 자동 매핑 (ClusterStore)

**위치:** `packages/server/src/cluster-store.ts`

#### 시그니처 구조
```typescript
interface SignatureData {
  name?: string;
  type: string;
  componentProperties?: Record<string, { value: string; type: string }>;
  parent?: ParentData;
  children?: SignatureData[];
}
```

#### variantMode
- **base**: componentProperties에서 value 제거, key만 사용
- **full**: VARIANT 타입은 value 포함, TEXT 타입은 value 제거

### 4.2 기본 매핑 규칙 (DefaultMappingRulesStore)

**위치:** `packages/server/src/default-mapping-rules-store.ts`

노드 이름에 keyword가 포함되면 해당 registry로 매핑

## 5. 환경 설정

### 5.1 서버 설정 (packages/server/config/server.env)
```env
PORT=5181
HOST=0.0.0.0
CORS_ORIGINS=*
ENABLE_DEBUG_JSON=false
```

### 5.2 클라이언트 설정 (packages/client/public/config.json)
```json
{
  "serverHost": "192.168.0.100",
  "serverPort": 5181,
  "appTitle": "AICraft Figma Viewer"
}
```

- `serverHost`: 빈 문자열이면 상대 경로 사용 (Vite proxy)
- `serverPort`: API 서버 포트

### 5.3 Vite 프록시 설정
```typescript
// packages/client/vite.config.ts
proxy: {
  '/api/figma-proxy': {
    target: 'https://api.figma.com',
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/api\/figma-proxy/, ''),
  },
  '/api': {
    target: 'http://localhost:5181',
    changeOrigin: true,
  },
}
```

## 9. 알아야 할 핵심 포인트

1. **시그니처에 위치 정보 미포함**: CSS 위치가 달라도 구조가 같으면 같은 시그니처
2. **variantMode 두 가지**: base (key만), full (variant value 포함)
3. **클래스 빈도 추적**: customAttrs.class가 객체로 빈도 저장
4. **프로젝트 격리**: 모든 데이터가 project_id로 분리됨
5. **독립 배포 가능**: server와 client 각각 별도 배포 가능
